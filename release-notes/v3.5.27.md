# v3.5.27

本次更新移除额外的 execution 执行策略，买卖委托按原网格价格提交，每张买单仅使用一格金额，避免跳格时自动补买、合并加量及盘口改价。

## 交易行为与配置变更

- 移除 `execution` 配置段及全部 11 项 `OPENSQT_EXECUTION_*` 环境变量，包括 Maker 额外保护距离、独立行情超时、PostOnly 专用退避、被动补格、近盘口拆批和跳格合并参数。旧配置中的这些值会被忽略，可直接删除，不会恢复旧的默认补格行为。
- 普通买单从当前网格下一格向下挂单，每张买单对应一格 `trading.order_quantity` 报价金额，数量仍按合约精度取整。行情跨越多个网格时不增加单张金额，也不补买漏格。
- 卖单按所属槽位价格加 `trading.price_interval` 提交，使用该槽位实际持仓数量；不再自动移到盘口附近，也不再将跳格合并持仓拆到其它槽位。若目标价已被已有卖单占用，则等待订单收敛，不挪到相邻价格。
- PostOnly 拒单使用普通 1 秒冷却，随后按当前网格和库存重新规划，不再使用专用指数退避或盘口版本重试门槛。批量提交仅遵守交易所批次上限，不按盘口距离拆批。

## 保留的交易保护

- 所有策略订单保持严格 PostOnly，卖单保持 ReduceOnly，不降级为 Taker。
- 保留唯一 WebSocket 行情源、订单流先于下单、槽位锁定、保证金守卫、健康检查、对账及 UNKNOWN 下单结果确认。
- 已进入交易所创建边界但结果未知的请求仍保留原订单身份，不因重试前库存变化而释放或重复下单。

## 监控与升级说明

- 面板移除本地盘口拦截、补格统计及相关配置展示，保留接受率、提交次数、PostOnly 拒单和买一/卖一。
- 买卖窗口大小仍控制订单规划；窗口为 3 时仍可能同时挂三档订单并连续成交，本次更新不限制短时间成交笔数。
- 原价会立即成交时，Binance 可拒绝该 PostOnly 委托；程序不会为了成交自动改价，因此该槽位可能需要等待行情变化。
- 已有仓位的启动恢复规则保持不变。恢复后的槽位目标价不等于真实成本保本价，本版本未修复旧仓低于真实成本卖出的可能性。
- 升级需替换可执行文件或拉取新镜像并重建容器。保留自己的配置和密钥；发行包中的 `config.yaml` 由模板生成。

## 验证与发行

- 覆盖跳格后每单保持一格金额、买卖原价提交、已有单槽持仓不自动拆分、普通拒单冷却、旧配置失效及未知订单身份保留的回归测试。
- 发布检查包括依赖校验、编译、静态检查、主程序漏洞扫描、打包回归、全量并发测试及前端测试。
- 提供 Linux amd64、Windows amd64、MacOS arm64 安装包及 SHA256 校验文件。
- Docker 支持 linux/amd64 与 linux/arm64：`ghcr.io/zuoban/opensqt_market_maker:v3.5.27`，同时更新 `latest`。
